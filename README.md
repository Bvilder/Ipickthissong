# 我选这首歌 · MUSIC PERSONA

移动端优先的音乐人格选择游戏。用户从 32 首歌里做 31 次二选一，系统根据**真实选择路径**生成六维音乐人格卡，并支持好友挑战对比默契度。

## 核心链路

```
首页（选玩法） → 选歌（32 强） → 淘汰赛（32→16→8→4→2→1） → 人格卡 → 分享图 / 挑战链接 → 好友对比默契度
首页 → 导入歌单 → A-Z 挑战（逐字母组内淘汰） → 音乐字母表 → 分享图
```

## 开始

```bash
npm run dev
```

## 人格是怎么算出来的

`lib/personality.ts` 是一个确定性规则引擎，输入完整选择路径，输出六维分数、人格标签与判词：

| 维度 | 主要信号 |
| --- | --- |
| 旋律偏好 | 胜出歌曲的抒情 / 文艺 / 温柔类标签占比 |
| 节奏敏感 | 嘻哈 / 电子 / 摇滚 / 节奏类标签的胜率 |
| 情绪深度 | 深情 / 脆弱 / 自省 / 遗憾类标签的胜率 |
| 怀旧倾向 | 胜出歌曲在曲库中的年代位置 + 早期 / 经典 / 重制标签 |
| 冷门挖掘 | 每次对决中是否选择了更靠后（冷门）的种子位 |
| 副歌执念 | 爆发 / 高音 / 张力 / 热血类标签的胜率 |

轮次越靠后权重越高，冠军单独加权 12%。同样的选择路径永远得到同样的结果。

### 切换为大模型

`app/api/generate-personality` 默认走本地规则引擎，配置以下环境变量后自动切换为 OpenAI 兼容接口（腾讯混元 / DeepSeek 均可），失败时静默降级：

```
LLM_API_KEY=xxx
LLM_BASE_URL=https://api.hunyuan.cloud.tencent.com/v1
LLM_MODEL=hunyuan-turbo
```

## A-Z 挑战

导入歌单（演示阶段直接用预置曲库）后，按歌名首字母分成 26 格 + `#`（数字/其他）：

- 中文歌按拼音首字母归类，预置曲库已在 `data/gem.json` 中标注 `letter`，接入真实歌单时由 `lib/pinyin.ts` 兜底计算
- 每个字母内打一场小组淘汰赛（含奇数轮空处理），只有一首的字母直接认领
- 全部字母走完 = 你的 A-Z 音乐字母表，人格引擎以 `mode: 'az'` 生成专属判词（提到填了多少格、纠结最久的字母）

## 好友挑战

挑战链接形如 `/?c=<base64url>`，编码内容为：

```ts
{ v: 1, artist, songs: string[], picks: number[], winner: number, tags: string[] }
```

好友打开后还原出**完全相同的 32 首歌与对阵顺序**，打完自动计算默契度：冠军一致性（40）+ 四强重合（25）+ 八强重合（20）+ 晋级路径差异（15），并给出共同四强与分歧最大的一首歌。不依赖后端存储。

## 歌手与曲库

| 歌手 | 曲目数 | 覆盖字母 |
| --- | --- | --- |
| 邓紫棋 G.E.M. | 45 | 19 |
| 周杰伦 Jay | 54 | 19 |

曲库为演示用预置元数据，接入 QQ 音乐开放平台后替换为官方数据。新增歌手只需：

1. 加一份 `data/xxx.json`
2. 在 `lib/musicProvider.ts` 的 `ARTISTS` 与 `LIBRARIES` 里注册

上层页面与组件无需改动。

- `lib/types.ts` — Song / Choice / PersonalityResult / ChallengePayload / Matchup
- `lib/musicProvider.ts` — **数据层唯一出口**，未来替换成 QQ 音乐开放平台 API 只需改这里
- `data/gem.json` — 预置曲库（仅元数据）

## 合规声明

本产品仅调用歌曲元数据用于互动选择游戏，**不提供音乐播放、下载或缓存功能**，不包含任何音频文件。所有音频收听行为均跳转至 QQ 音乐官方平台完成。
